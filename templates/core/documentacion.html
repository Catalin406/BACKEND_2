    {# ===== 1. PROPÓSITO ===== #}
    1. Propósito

    {{ NOMBRE_COMERCIAL }} es un sistema de matrícula para una academia tecnológica. Los estudiantes navegan la oferta académica y agregan cursos, bootcamps o talleres a un carro de matrícula persistente guardado en PostgreSQL. Al confirmar, el sistema valida que cada curso tenga al menos un cupo libre, cambia la matrícula a Pagado, descuenta un cupo por curso y emite una inscripción oficial con código UUID.

    El Coordinador Académico administra áreas y cursos y cambia el estado de las matrículas. Si cancela una matrícula pagada, los cupos se liberan automáticamente para otros estudiantes.

    3. Matriz de roles y permisos
    RolEndpoints
    PúblicoGET /api/cursos/, GET /api/areas/
    EstudianteGET/POST/DELETE /api/carro-matricula/, POST /api/matriculas/confirmar/, GET /api/mis-matriculas/
    CoordinadorPOST/PUT/DELETE /api/cursos/, PATCH /api/matriculas/{id}/estado/
    Sin token la API responde 401; con token pero con otro rol responde 403. El rol se lee desde el claim rol del JWT y se contrasta con la base de datos. Las pantallas HTML no tienen login: la seguridad por roles vive en la API.
    {# ===== 4. FLUJO ===== #}
    4. Flujo de matrícula
    1. 1
      Carro: el estudiante agrega cursos. Se rechazan duplicados, cursos inactivos, sin cupos o ya inscritos. Agregar no descuenta cupos.
    2. 2
      Confirmación: en una sola transacción se bloquean el carro y los cursos (SELECT … FOR UPDATE, en orden por id) y se valida el cupo de cada curso. Si alguno falla, se revierte todo y la API responde 409.
    3. 3
      Pagado + inscripciones: se crea la matrícula, se congela el costo, se descuenta 1 cupo por curso, pasa a Pagado y se emite una inscripción UUID por curso. El carro se vacía.
    4. 4
      Cierre: el coordinador marca Completado o Cancelado. Al cancelar una matrícula pagada, se libera 1 cupo por curso y sus inscripciones quedan inactivas.
    {# ===== 5. ESTADOS ===== #}
    5. Estados y transiciones permitidas
    {% for valor, etiqueta in estados %}{{ etiqueta }}{% endfor %}
    • Pendiente → Cancelado
    • Pagado → Completado (el estudiante terminó el curso)
    • Pagado → Cancelado (libera cupos)
    • Completado y Cancelado son estados finales: cualquier otro cambio responde 400.
    {# ===== 6. SWAGGER ===== #}
    6. Cómo probar con Swagger paso a paso
    1. 1
      Abre /api/docs/ y ejecuta POST /api/auth/login/ con un usuario de prueba.
    2. 2
      Copia el valor access, presiona Authorize, pégalo y confirma.
    3. 3
      Como estudiante: GET /api/carro-matricula/, luego POST /api/carro-matricula/ con {"curso": id}. Repite el mismo curso para ver el error 400.
    4. 4
      Ejecuta POST /api/matriculas/confirmar/: obtendrás 201 con los códigos UUID, o 409 si algún curso quedó sin cupo.
    5. 5
      Inicia sesión como coordinador, autoriza el nuevo token y ejecuta PATCH /api/matriculas/{id}/estado/ con {"estado": "CANCELADO"} para liberar los cupos.
